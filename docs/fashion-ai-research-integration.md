# خطة دمج أبحاث ومشاريع Fashion AI في 3D Patrons

## القرار التنفيذي

هذه المشاريع تغطي ثلاث مشكلات مختلفة يجب أن تبقى منفصلة:
1. فهم صورة الملابس ثنائية الأبعاد: كشف القطعة، فئتها، حدودها، أجزاؤها ومعالمها.
2. إعادة بناء الملابس ثلاثية الأبعاد: استنتاج سطح/شبكة قطعة من صورة أو بيانات مرجعية.
3. العرض والتجربة الافتراضية: تركيب صورة ملابس على صورة شخص أو تخصيص نموذج منتج.

يبقى محرك الباترون الهندسي الحالي مصدر الحقيقة لأبعاد القطع وخطوط الخياطة. صورة try-on أو mesh مستنتج لا يساوي باتروناً قابلاً للقياس والتصنيع.

## المعمارية المقترحة

### A. محلل صور الملابس — 2D Garment Understanding

صورة ← كشف الشخص/القطعة ← تصنيف الفئة ← segmentation mask ← landmarks مع visibility/confidence ← نتيجة قابلة للمراجعة.

- مخطط DeepFashion2 هو المرجع الأساسي لتوحيد الفئات والأقنعة والنقاط.
- FashionAI مرجع إضافي لنقاط الكتف والرقبة والأكمام والخصر والحاشية، مع mapping صريح بين تعريفات المجموعتين.
- لا تجمع landmarks من مجموعات مختلفة دون تحويل موثق؛ ترتيب النقاط ودلالتها يختلفان حسب الفئة والمجموعة.
- خزّن مصدر النموذج وإصداره وأبعاد الصورة والتحويلات العكسية ودرجة الثقة لكل نقطة.
- اسمح بتصحيح النقاط يدوياً قبل استخدامها.

### B. جسر من الصورة إلى هندسة القطعة

landmarks أو segmentation وحدها لا تنتج باترون تصنيع. المطلوب:
1. معايرة المقياس بمرجع معلوم أو قياسات موثوقة؛ وإلا فالنتيجة نسبية.
2. استنتاج خطوط بنيوية أولية: neckline وshoulder وarmhole وwaistline وside seam وhemline.
3. تحويلها إلى منحنيات وقيود داخل PatternDocument الحالي.
4. تطبيق قواعد الباترون والراحة وبدلات الخياطة من محرك CAD، لا من نموذج الرؤية.
5. إظهار عدم اليقين وطلب تصحيح يدوي عند الحجب أو نقص الرؤية.

### C. إعادة بناء الملابس 3D

- اجعل DeepFashion3D V2 معيار المقارنة الأول: mesh مسجل حسب الفئة، point cloud كثيف، texture maps وخطوط خصائص.
- ابدأ بعينة أصول صغيرة ومسموح بها قانونياً، ولا تضمّن مجموعة البيانات كاملة في مستودع الموقع.
- ابنِ محول أصول إلى glTF/GLB يحافظ على UV والخامات ويتحقق من الاتجاه والوحدات والمقياس.
- قارن النماذج المستنتجة بخطوط الرقبة والخصر والحاشية والسطح المرجعي.
- استخدم 3D-Magic-Mirror في بيئة GPU منفصلة، لا كاعتماد داخل GitHub Pages.

### D. تجربة الملابس بالصور — Virtual Try-On

- CatVTON مرشح لتجربة الملابس 2D على صورة شخص.
- DeepFashion_Try_On وFashionGAN مرجعان بحثيان للمقارنة، لا أساساً لخدمة إنتاجية جديدة.
- المخرجات صور تركيبية وليست محاكاة قماش فيزيائية، ولا تثبت أن الملابس تناسب قياسات الجسم.
- لا تربط ناتج try-on بمحرك الباترون على أنه قياس أو حقيقة هندسية.
- لا تدمج CatVTON أو DeepFashion_Try_On أو FashionGAN في منتج تجاري قبل مراجعة الشروط والحصول على الإذن اللازم.

### E. تخصيص المنتج في Three.js

استفد من Product_3D في تجربة تخصيص سطح القماش:
- اختيار اللون والخامة.
- رفع شعار أو صورة.
- تحريك الطباعة وتغيير حجمها ودورانها على UV canvas.
- حذف العناصر وإعادة ترتيبها.
- معاينة أمامية وخلفية وتصدير صورة/ملف تصميم.

يجب تطبيق ذلك على garment mesh صادر من نظامنا، مع حفظ التصميم كبيانات قابلة للتحرير، لا كصورة مسطحة فقط.

## ترتيب التنفيذ المقترح

### المرحلة 1 — عقود البيانات والمحوّلات

- إنشاء GarmentVisionResult يحوي الفئة، bounding box، mask، landmarks، visibility، confidence، مصدر النموذج وإصدار مخطط النقاط.
- إنشاء mapping موثق لفئات ونقاط DeepFashion2 وFashionAI.
- إضافة أمثلة JSON اصطناعية واختبارات تحويل الإحداثيات والنقاط المخفية.
- عدم إضافة بيانات مجموعات خارجية أو أوزان نماذج إلى المستودع.

**بوابة القبول:** اختبارات تؤكد ثبات إحداثيات النقاط بعد resize/crop/flip وإرجاعها إلى الصورة الأصلية، مع رفض نقاط غير صالحة.

### المرحلة 2 — تجربة محلل صور

- بناء واجهة رفع صورة وعرض overlay للنقاط والقناع.
- دعم التصحيح اليدوي وحفظ النتيجة.
- ربط النتيجة لاحقاً بمحول الخطوط الأولية إلى PatternDocument.
- إبقاء مقياس القطعة مجهولاً حتى توفير مرجع قياس.

**بوابة القبول:** يستطيع المستخدم تصحيح النقاط ومشاهدة خطوط أولية مع تحذيرات واضحة دون ادعاء أنها باترون إنتاجي.

### المرحلة 3 — مكتبة أصول DeepFashion3D

- جرد الأصول المصرح بها بعد استكمال شروط التنزيل.
- استيراد عينة صغيرة إلى مختبر 3D.
- بناء فاحص mesh وUV وmaterials وscale وfeature-lines.
- عرض الأصول المرجعية بجانب قطعنا لمقارنة الشكل.

**بوابة القبول:** استيراد GLB قابل للتكرار مع حفظ UV والخامة والوحدات وتقرير فحص لكل أصل.

### المرحلة 4 — تخصيص المنتج ثلاثي الأبعاد

- إضافة محرر خامة/طباعة على القطعة الحالية.
- حفظ مواضع الطباعة كبيانات مستقلة عن texture baking.
- تصدير معاينة وصورة تصميم.

**بوابة القبول:** تعود الطباعة إلى موضعها الصحيح بعد إعادة فتح المشروع وتغيير الكاميرا.

### المرحلة 5 — خدمة Virtual Try-On اختيارية

- تقييم تشغيل CatVTON على خادم GPU خاص بعد حسم الترخيص.
- واجهة adapter مستقلة لا ترتبط بمحرك CAD.
- طابور مهام وحدود لحجم الصورة وحذف تلقائي للصور وموافقة المستخدم قبل المعالجة.
- لا تستخدم GitHub Pages لتشغيل PyTorch أو تخزين صور المستخدمين.

**بوابة القبول:** اختبار end-to-end على صور مرخصة وتقييم جودة/فشل وزمن/تكلفة الخدمة قبل إتاحتها.

### المرحلة 6 — بحث إعادة بناء 3D من صورة

- تجربة 3D-Magic-Mirror على بيئة منفصلة.
- المقارنة بأصول DeepFashion3D V2 عند توفر إذن البيانات.
- قياس Chamfer/normal/feature-line errors ومراجعة mesh بصرياً.
- لا يعتمد النموذج إلا إذا أثبت ثباته عبر أنواع ملابس وزوايا متعددة.

## ما لن ندّعيه

- أن try-on 2D يحاكي شد القماش أو الملاءمة الحقيقية.
- أن landmarks وحدها تنتج باتروناً صالحاً للقص.
- أن صورة واحدة تكفي دائماً لاستنتاج الأبعاد الثلاثية الدقيقة للقطعة.
- أن Fashion-MNIST مناسب لتدريب نظام فهم ملابس دقيق.
